# Decision Log

## D-001 — Do not build a winery directory as the core product

**Status:** Accepted  
**Reason:** local directories already provide broad map/discovery coverage.

## D-002 — Validate repeat-purchase / measurable winery ROI as primary wedge

**Status:** Active hypothesis  
**Reason:** stronger potential payer value and differentiation than generic discovery.

## D-003 — Marketplace is not MVP

**Status:** Accepted  
**Reason:** payment, fiscalization, alcohol age, stock and logistics complexity precede proof of demand.

## D-004 — Booking starts as lead/request, not full payment

**Status:** Accepted  
**Reason:** validate demand and winery operations before taking transaction/regulatory burden.

## D-005 — Web first

**Status:** Accepted  
**Reason:** SEO, QR and mobile web can validate core jobs; native app is gated.

## D-006 — Occasion-first discovery is tested before advanced Taste Match

**Status:** Active hypothesis  
**Reason:** novice users may understand food/occasion/price better than tannin/body.

## D-007 — Wine Passport is not assumed to be retention

**Status:** Accepted guardrail  
**Reason:** must pass QR/save/return/reorder behavior gates.

## D-008 — Official/primary sources outrank commercial directories

**Status:** Accepted  
**Reason:** registry/geography/legal identity requires provenance and current status.

## D-009 — Draft 2026 wine law is not treated as enacted law

**Status:** Accepted  
**Reason:** public consultation/draft status at research cut-off; re-check before implementation.

## D-010 — No infrastructure theater

**Status:** Accepted  
**Reason:** modular monolith and PostgreSQL are default if build is authorized.
